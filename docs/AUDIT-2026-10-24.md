## Decisions and their limits

1. Keep the approved dirty `yesko-local` checkout in place, with an external immutable baseline and snapshot-based review diffs. A HEAD-based fresh worktree/review would omit the user's uncommitted renamed package. Cost: changes remain reviewable local edits; rollback/review uses the external snapshot instead of new commits.
2. Condition references follow actual evaluation timing: prior results for when/wait, current stored result also allowed for assertion equals; local assertion/wait paths remain local. Cost of a wrong interpretation would be workflow compatibility, covered by explicit regressions.
3. Use atomic no-overwrite rename and fail closed where unsupported; both host ext4 and NTFS3 support were independently tested. Cost: cross-filesystem/unsupported filesystems return unsupported instead of attempting an unsafe fallback.

## Explicit validation limits

- Real polkit approval/cancel/timeout, package upgrades, network/storage/power changes and physical-device/Docker/SSH/Android/VM/restic scenarios still require disposable configured environments; no destructive daily-system test was run.
- Locks coordinate cooperating writers. Arbitrary external in-place writes do not participate in those locks; the adapter is not an OS transaction/sandbox over such writers.
- Dynamic values and model-level validators depending on unresolved references are validated at runtime. Preflight does not predict values that a prior action has not produced.
- File revisions remain byte SHA256. Undo restores the backed-up mode; a later mode-only change is outside that byte revision contract. No silent revision-format change was introduced.
- Permissive Wayland session-entry detection and endpoint-only drag confinement were recorded as follow-up concerns, without a proven supported-host/app failure; they were not presented as repaired exploits.
- The documented artifact retention/quota and paired20-task model-token benchmark gates remain unchanged. Legacy remains the default profile.
