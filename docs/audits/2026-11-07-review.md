## Confirmed findings

### F4 — P2: default-seat pointer rounding crosses a checked boundary

Source: `server.py:798`, `trust.py:284`, `input.py:244`.

`pointer(click, x=639.6, y=5)` is checked at the supplied floating-point position.
On the default seat, delivery rounds it to `(640,5)`. With an allowed Kitty
window covering x=[0,640) and an out-of-scope Firefox window covering
x=[640,1440), the real guard accepts 639.6, then production input code dispatches
`movecursor 640 5` and issues the left click. Thus the delivered coordinate is
outside the region the guard approved.

Evidence: auditor and independent reviewer ran
`desktop/fractional_pointer_repro.py` through the public `server.pointer` path.
The guard and rounding code are production code; compositor IPC and the final
wire click are simulated. Actual Firefox receipt was not observed on a live
compositor. The demonstrated issue is default-seat confinement validation versus
delivery mismatch; do not generalize it to named-seat behavior.

Fix direction: validate the exact coordinates that will be delivered, including
seat-specific conversion, before any pointer action.

### F3 — P2: launch can claim a concurrent human window

Source: `server.py:1649–1656`, `server.py:1776–1789`.

During `launch('google-chrome', workspace='2')`, the matcher accepts any newly
observed window with a fuzzy matching app class, even when it appears on the
human's workspace 1. That window is then added to the owned set and moved to 2.
The launch docstring promises not to take a window the human opens meanwhile.

Evidence: `desktop/launch_human_window_repro.py` exercises public `launch()` with
isolated IPC fixtures. The reviewer independently reran it with a valid window
address (`0xabc123`); dispatch included
`movetoworkspacesilent 2,address:0xabc123` and ownership was assigned.
This proves the decision path for the supplied event ordering; a concurrent
human/browser race was not reproduced on a live compositor. The single-instance
fallback is intentional; class equality alone does not establish provenance.

Fix direction: require stronger window provenance, or report ambiguous launch
association without claiming/moving that window.

### F1 — P3: foreground keyboard reports focus untouched after changing it

Source: `server.py:908–918`, `server.py:1179–1193`.

For `keyboard(action='key', window=<nonfocused window>, background=false)`,
the target is focused first. The shared helper then snapshots the already
changed seat and can report "the human's focus untouched". The focus takeover
itself is permitted by foreground mode; the inaccurate whole-call receipt is
the defect.

Evidence: real installed-wheel Hyprland 0.53.3 VM trace:
`/workspace/.omnimcp-runtime/hypr-inspect/results/workspace-probe.json`.
With special:notes open over workspace 2, a key targeting the workspace-1 window
closed the special workspace and changed focus/workspace to 1, while the reply
said focus untouched. Tested `background=true` Escape calls preserved the
special workspace and human focus. All 53 Python source files were compared
against the wheel used in that VM and matched byte for byte.

Fix direction: measure seat state before the complete foreground operation and
describe the actual focus takeover in its receipt.

### F2 — P3: accepted cancellation produces shell failure

Source: `core_cli.py:125`, `core/engine.py:568–575`.

The worker accepts cancellation and returns `status=cancellation_requested`,
but CLI success-status classification excludes it and exits 1. Scripts therefore
see failure even when the cancellation request was accepted. Acceptance remains
asynchronous and is not a promise that the job has already stopped.

Evidence: an isolated real worker/socket and harmless sleeping child returned
`{"status":"cancellation_requested","job_id":"jfbe906eb7092465a"}` with
CLI exit 1; subsequent polling reached job/result status cancelled. The auditor
cleaned up its own worker. The reviewer independently checked the real engine
and CLI classification.

Fix direction: classify accepted cancellation as a successful CLI request while
preserving the asynchronous status in JSON.
