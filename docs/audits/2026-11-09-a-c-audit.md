## Threat model

- Буруу tool дуудлага болон дэлгэц/файл/карт/цонхны гарчгаар ирэх итгэлгүй өгөгдөл.
- Policy, lifecycle, malformed протокол, stale state, файл/backup-ийн integrity.
- Нууцлал: journaling идэвхтэй ч text recording унтраалттай байх үеийн хадгалалт.
- Өөр UID-ийн хандалт ба ижил UID-ийн процессын эрхийг ялгасан. Ижил UID-ийн
  arbitrary command нь зорилготой боломж; tool policy нь OS sandbox биш.
- FIFO болон Canvas symlink repro нь хувийн/бичих боломжтой coordination замд
  өөрчлөлт хийх урьдчилсан нөхцөлтэй. Үүнийг root эрх авах халдлага гэж дүгнээгүй.

## Батлагдсан finding

### AC01 — P2: Canvas backup амжилттай гэж буцаасан ч эх агуулга үлдэхгүй

- Код: `src/omnimcp/canvas.py:322–344`.
- Урьдчилсан нөхцөл: revision-оор нэрлэсэн `.bak` зам эх Canvas руу заасан
  symlink хэлбэрээр аль хэдийн байна.
- Repro: existing backup-ийн `read_bytes()` эх агуулгатай тэнцэж шалгалтыг давна.
  Canvas атомикаар солигдсоны дараа backup link шинэ агуулга руу заана.
- Нотолгоо: `receipt_is_link=True`, `backup_equals_old=False`,
  `backup_equals_new=True`. Нэмэлт audit тест нь бодит private-path шалгалттай
  `_write`-ийг дуудаж, эх байтууд хадгалагдах ёстой assertion дээр унана.
- Шалтгаан: existing backup-ийн нэр, агуулгыг шалгахдаа symlink дагаж уншдаг.
- Хамгийн бага засвар: backup-ийг no-follow descriptor-оор нээж regular файл,
  identity болон агуулгыг шалгах; баталгаа байхгүй бол replace хийхээс өмнө татгалзах.

### AC02 — P2: Emergency stop FIFO файл дээр гацна

- Код: `src/omnimcp/cli.py:209`, `:247`.
- Урьдчилсан нөхцөл: `cli.lock` эсвэл `state.json` нь тухайн UID-ийн mode-0600 FIFO.
- Repro: CLI lock-ийн plain `open()` болон beacon-ийн `read_text()` блоклоно.
  Тусгаарласан child process 3 секундэд дуусаагүй; хоёр зам тус бүр батлагдсан.
- Шалтгаан: regular-file шалгалтаас өмнө blocking open/read хийдэг.
- Хамгийн бага засвар: nonblocking + no-follow open, `fstat` regular/owner/mode,
  хязгаартай уншилт; буруу state дээр гацалгүй тодорхой алдаа буцаах.
- Энэ нь emergency-stop availability асуудал; бүх process-ийг хаана гэсэн шинэ
  амлалт эсвэл өөр UID-ийн privilege escalation гэсэн дүгнэлт биш.

### AC03 — P2: JPEG-гүй grim дээр default screenshot/zoom ажиллахгүй

- Код: `src/omnimcp/screenshot.py:112–165`.
- Бодит орчин: Ubuntu 26.04-ийн `grim 1.4.0+ds-2build3`, Hyprland 0.53.3.
- Repro: default capture зөвхөн JPEG оролддог; `grim failed: jpeg support disabled`
  алдаан дээр шууд зогсоно. PNG capture ажилладаг.
- Бодит marked suite хоёр fresh guest дээр тус бүр **11 passed, 5 failed**.
  Унасан тестүүд: `test_screenshot_per_monitor_maps_back`,
  `test_screenshot_live_monitor_and_region`, `test_screenshot_roundtrip_file_mode`,
  `test_screenshot_roundtrip_image_mode`, `test_zoom_roundtrip_file_mode`.
- Хамгийн бага засвар: формат боломжгүйг ялгаж PNG fallback болон scaling/byte
  budget-ийг хадгалах; дэмжих grim capability-г setup-д тодорхой болгох.
- Doctor-ийн dependency шалгалт existence-only боловч бүтэн doctor бодит screenshot
  хийдэг тул энэ алдааг мэдээлнэ. Doctor бүхэлдээ falsely passes гэж дүгнээгүй.

### AC04 — P2: Named-seat keyboard connection дээр төхөөрөмжүүд хуримтлагдана

- Код: `src/omnimcp/wire.py:354–390`, `src/omnimcp/input.py:147–173`.
- Нөхцөл: named-seat VirtualKeyboard connection-ийг дахин ашиглан text илгээнэ.
- Protocol repro: call бүр manager/keyboard resource шинээр үүсгэж, устгахгүй.
- Бодит VM repro: нэг connection, гурван `type_text` дуудлага. Бие даасан
  `hyprctl -j devices` тооллого **3 → 4 → 5 → 6**, connection хаахад **3** болсон.
- Энэ нь connection амьд байх хугацааны accumulation; close хийсний дараах
  байнгын leak гэж нэрлээгүй. Cached worker connection удаан амьдрах замтай.
- Хамгийн бага засвар: manager/keyboard-ийг хязгаартай дахин ашиглах эсвэл
  дэмжигдэх protocol teardown-ийг success/error бүх замд хийх.

### AC05 — P2: Journal `append_text`-ийг plaintext хадгална

- Код: `src/omnimcp/journal.py:282–299`, `src/omnimcp/server.py:2730–2751`.
- Нөхцөл: journal идэвхтэй, `OMNIMCP_JOURNAL_TEXT=0`.
- Repro: `text` digest болж, `append_text` literal хэвээр үлдэнэ. Бодит
  `journal.record('kanban_update', …)`-оор synthetic note NDJSON-д хадгалагдсан.
- Journal анхдагчаар унтраалттай, файл нь хувийн; opt-in журналын redaction gap.
- Хамгийн бага засвар: free-text талбаруудын төвлөрсөн ангилалд `append_text`
  нэмэх, бусад нэртэй чөлөөт текстийг contract-тай нь тулгах; replay болон
  explicit text opt-in-ийн утгыг хадгалах. Энэ нь өмнөх A24-ийн нээлттэй хэсэг.

### AC06 — P3: Malformed D-Bus array/variant зөв протоколын алдаа болохгүй

- Код: `src/omnimcp/dbuswire.py:189–201`.
- Repro: array-ийн зарласан byte length 4 байхад item дараагийн аргументын
  байтуудыг уншин `[['ABCD'], 777]` гэж буцаана. Хоосон/буруу variant signature
  нь `DBusError`-ийн оронд `IndexError` / `KeyError` гаргана.
- Hypothesis хамгийн бага counterexample-ийг `0000` байт хүртэл багасгасан.
- Хамгийн бага засвар: nested array-ийн хил бүрийг item decode-д мөрдүүлэх,
  signature-г validate хийж malformed input-ийг domain error болгох.
- Буруу decode эсвэл tool failure батлагдсан; код ажиллуулах, authorization
  bypass эсвэл амьд malicious AT-SPI аппын exploit батлагдаагүй.

## Conditional candidate ба няцаасан дүгнэлт

- **C1 — P3 candidate:** `cli.py:183–190,238–255` held lock-ийн raw PID-г birth
  time/holder identity-гүй signal хийнэ. Mocked kill дээр mismatch батлагдсан ч
  жирийн lifecycle-аас wrong-target kill болох PID-reuse repro хараахан байхгүй.
- **C2 — P3 candidate:** `a11y.py:419–423,514–552` node budget 2 байхад synthetic
  5,000 child бүгд materialize/queue болно. 128 MiB message cap, timeout байна;
  бодит аппын memory exhaustion эсвэл availability impact батлагдаагүй.
- **Няцаасан:** VirtualPointer missing-manager constructor failure-ийн байнгын
  socket leak. Бодит FD-тай 1,000 алдаа, GC унтраалттай үед count **6 → 6 → 6**.
  Fake socket-ийн `closed=False` нь байнгын leak-ийн хангалттай нотолгоо биш.
