## Confirmed

- **P2 Canvas backup integrity:** `src/omnimcp/canvas.py:322`–`344`: a backup receipt should preserve original bytes. A preexisting revision-named backup symlink to the Canvas passes the existing-name check, then tracks the newly replaced Canvas. Output: `receipt_is_link=True backup_equals_old=False backup_equals_new=True`. Source verifies bytes following the symlink, not backing-file identity. Require existing backup opened no-follow and checked regular via descriptor, verify bytes, fail closed before replacement. Repro requires ability to create a predictably named adjacent file; no cross-user boundary is asserted. P2 because successful edits can leave no original backup despite a success receipt.
- **P2 Journal text leak:** `src/omnimcp/journal.py:282`–`299`, `server.py:2730`: configured journaling with text opt-in disabled should digest free-text notes. `journal.redact({'text':'fixture','append_text':'fixture'})` outputs a digest for `text` but literal `append_text`. Real `kanban_update` records that free-form field. Extend centralized recursive text classification to `append_text`, preserve text opt-in; evaluate other free-form parameters against documentation. P2 due to persistent private information in explicitly enabled journal, itself private and disabled by default. Repro tests the exact production redactor, not a real board.
- **P2 stop can hang:** `src/omnimcp/cli.py:247`, `cli.py:209`: emergency stop should finish or fail promptly with malformed state. Owned mode-0600 FIFOs at `cli.lock` and `state.json` each caused `blocked past 1 second`; only the isolated subprocess was terminated by timeout. Ordinary blocking open/read follows the FIFO; state checks ownership/mode/symlink but not file type. Use nonblocking no-follow descriptor opens and fstat regular, owner, mode, and bounded reads, including both paths. P2 because the emergency command cannot complete while state is invalid; it requires corruption or same-UID creation and is not a cross-UID privilege issue.
- **P2 compositor resource growth:** `src/omnimcp/wire.py:356`–`390`, `input.py:147`–`173`: named-seat cached keyboard should use bounded server objects. Two calls recorded `keyboard binds 2 creations 2`, with distinct keyboard IDs and no teardown. Both manager and keyboard objects are created per call; the connection persists. Reuse a bounded manager and keyboard or destroy supported protocol objects on all paths; verify exact manager lifecycle against the protocol. P2 for repeated normal operation potentially exhausting resources; protocol-level reproduction only, no live compositor resource measurements.
- **P3 D-Bus decoder validity:** `src/omnimcp/dbuswire.py:189`–`201`: decoded items must remain within their declared array and malformed variants must become `DBusError`. Array declared four bytes returns `[['ABCD'], 777]` while consuming bytes outside its boundary. Empty/invalid variant signatures raise `IndexError` / `KeyError`. Track nested item boundaries and validate signatures, converting malformed input to protocol errors. Malformed responses can yield wrong decoded data or a failed tool call; no privilege consequence or live malicious application demonstrated. P3.

## Candidates and rejected claims

- **P3 candidate, PID identity:** `src/omnimcp/cli.py:183`–`190`, `:238`–`255`; `verbs.py:388`–`405`. A held lock is treated as proof its stored raw PID identifies its actual holder. Holding a synthetic lock containing 424242, with `os.kill` mocked, made `stop()` call `kill(424242, SIGTERM)` and print success. Process birth identity and lock holder are not checked. Validate holder identity using a robust kernel-backed strategy and recheck start time immediately before signal. The repro artificially mismatches content; a normal persistent mismatch and PID reuse race remain unproved, and same-UID tampering is not a separate security boundary. Severity reflects conditional wrong-process termination, not demonstrated routine production occurrence.
- **P3 candidate, accessibility fanout:** `src/omnimcp/a11y.py:419`–`423`, `:514`–`552`. Budget should bound traversal work; fake 5,000-child response with max_nodes=2 yields two nodes and `truncated=True`, but builds/queues all direct children. Account for queued work and avoid allocating unnecessary children where possible; bounding only the stack does not prevent complete D-Bus reply decoding. Legal 128 MiB message cap and finite timeout constrain exposure; no real app impact or memory exhaustion demonstrated, so candidate rather than established availability bug.
- **Reject claimed persistent FD leak on pre-seat constructor failure:** `src/omnimcp/wire.py:132`–`146` does not explicitly close on failure, but fake socket `closed=False` is insufficient. 1,000 failures using real duplicated socket FDs with GC disabled yielded `before=6 after=6 after_gc=6 collected=0` after exceptions were handled. Explicit cleanup is still defensive for retained traceback or other ownership/lifetime scenarios. This experiment exercises missing-manager failure with send/roundtrip stubbed; it cannot prove all error paths leak-free.

## Additional live-VM finding: missing JPEG support

**Confirmed P2 compatibility failure:** `src/omnimcp/screenshot.py:111`–`162`, `:410`–`422`; `docs/start.md:5`–`7`. The published setup calls for `grim` without stating JPEG-enabled support is required, and a supported default screenshot/zoom should work with an installed grim that supports PNG. The preserved official Ubuntu 26.04 / Hyprland 0.53.3 VM log `vm/results/pytest.log` records 11 passed and five failed live tests, all because `grim failed: jpeg support disabled`; `vm/results/pytest-exit.txt` is 1. Those tests cover monitor/region screenshot and MCP screenshot/zoom. PNG desktop acceptance also passed according to the VM operator; that is separate evidence, not a claim every PNG fallback fits the transport budget.

Independent, mock-backed reproduction: `.venv/bin/python /workspace/.omnimcp-runtime/audit-ac-2026-11-09/review/grim_formats.py` gives `lossless False error grim failed: jpeg support disabled` and `lossless True result (b'png fixture', 'png', 1)`. The fake grim returns failure for JPEG and succeeds for PNG. `_fit_ladder` uses JPEG only by default, and `_grab_fitting` exits on the first failed format without trying an alternative. `_grab_toplevel` also broadly reclassifies any grim error as no toplevel support. P2 is appropriate because the default screenshot and zoom functions fail on the tested configuration; this is not evidence of failure on JPEG-enabled builds.

Minimum fix: detect unavailable JPEG encoding and retry PNG with a budget-aware scaling strategy, preserving truthful metadata and meaningful errors; add a regression with a JPEG-disabled grim and a live VM check. Alternatively explicitly require JPEG-enabled grim and give a precise setup error, though that leaves this otherwise PNG-capable configuration unsupported. `cli._check_deps` checks executable presence only, but **doctor as a whole does run** `_check_screenshot()` using the default capture, so it would report the JPEG error rather than falsely pass all checks. No VM or source files were modified in this review.
